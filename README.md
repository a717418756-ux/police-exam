# 短線雷達 StockRadar Pro

> 台股／美股量化分析 PWA — 從「市場→產業→個股→機構足跡」多維度決策平台
> 版本 v49｜繁體中文｜手機／Boox e-ink 優化

一個接近量化分析平台雛型的個人交易決策系統。核心理念不是「再多一個技術指標」，而是**多維度交叉驗證 + 看穿主力與散戶行為**——當所有人都用 AI 分析股票，優勢不在看到訊號，而在知道多少人跟你看到同一個訊號。

---

## 一、系統架構

```
前端 (GitHub Pages, 純 JS PWA)
   │
   ├── 資料查詢 ──→ Cloudflare Workers (快, 全球節點)
   │                   └→ Yahoo Finance / TWSE / 期交所 / FinMind
   │
   └── 雲端備份 ──→ Google Apps Script (沿用舊備份)
                       └→ 交易日誌雲端同步

本機儲存：IndexedDB (交易紀錄主要存這，離線可用)
```

**雙後端設計**：查詢走 Workers（快），備份走 GAS（沿用）。兩者功能完全對等（9 個端點），互為備援。

## 二、判斷流水線

```
① 四態 Regime  ──→ 判斷市場環境（多頭/空頭/盤整/高波動危險），決定該信哪些工具
② MTF 多框架   ──→ 月週日定大方向（大週期定調、小週期找進場）
③ 七維共振      ──→ 趨勢/動能/籌碼/結構/情緒/相對強弱/週期，依 Regime 動態加權
④ 貝氏機率      ──→ 用該股歷史訊號命中率輸出真機率（非燈號），機率校準迴路自我檢驗
⑤ 主力行為      ──→ OBV/KBAR偷跑偵測，推估吸籌/洗盤/出貨/誘多誘空
⑥ 主力縱深      ──→ FinMind千張大戶剪刀差、法人借券空單（部位背離統計優勢）
⑦ 反明牌雷達    ──→ 量化散戶擁擠度，偵測明牌陷阱
⑧ 智慧停損      ──→ 結構位（原始市價）+動態緩衝，防被掃後反向走
⑨ 出手紀律門    ──→ 七道關卡濃縮為出手/禁止裁決，綠燈附執行計畫（部位/停損/停利/VaR）
```

## 四、交易日誌系統（journal.js）

核心設計：**只填 5 格，其餘自動算**。

**只需填**：進場日、出場日、代碼、進場價、出場價
**系統自動**：
- 抓區間 K 線算 MAE（最深虧）/ MFE（最高賺）— 用未還原市價對齊使用者輸入
- 盈虧%、抱倉天數、自動判定凹單
- 記錄進場日的公式分數 + **貝氏預測勝率**（供機率校準）
- 方向一致性檢查（順公式/逆公式進場）

**進階功能**：
- 🧪 模擬單、分批進場/加碼、分批出場/停利
- 真實勝率 vs 帳面勝率（凹單僥倖判定）
- **成本後真相**：扣除來回成本0.585%後的真實報酬/勝率
- **Wilson 信賴區間**：勝率的可信度區間，樣本越少區間越寬（誠實揭露）

**Markdown 匯出**（給 AI 優化公式用）：
- 真實 vs 模擬對照、勝率信賴區間
- **期望值盲測對照**：1000次隨機重抽樣基準 vs 你的系統，證明是否為真Alpha
- ★ 進場公式分數 vs 結果對照表、**機率校準度**（預測 vs 實際，避免假高分）
- 順公式 vs 逆公式 MAE 統計、加碼/分批出場決策分析、時間停損驗證

## 五、反散戶哲學

| AI 散戶的可預測行為 | 本系統的反制 |
|---|---|
| 全部看到同樣教科書訊號 | **反明牌雷達**量化擁擠度 |
| 停損全放支撐下方/2×ATR | **智慧停損**放結構外緩衝區（原始市價） |
| 用槓桿真金白銀照做 | **融資融券**直視散戶部位 |
| 看不到主力 | **OBV/KBAR偷跑 + 主力行為推估** |
| 看不到大戶/法人 | **FinMind主力縱深**：千張剪刀差、法人借券 |

核心：**擁擠 + 主力反向 = 明牌陷阱**。出手紀律門絕不逆聰明錢操作（R7大戶法人關卡）。

## 七、部署

### 前端（GitHub Pages）
1. 所有前端檔案上傳到 repo 根目錄（不開子資料夾）
2. Settings → Pages → 選 main 分支根目錄
3. `Code.gs` 與 `worker.js` **不上傳**（那是後端）

### 後端 A：Cloudflare Workers（查詢，推薦）
1. dash.cloudflare.com → Workers & Pages → Create Worker
2. 貼上 `worker.js` → Deploy
3. （選用雲端同步）建立 KV namespace 名為 `SYNC`，綁定到 Worker
4. 複製網址 → PWA 設定「資料查詢網址」

### 後端 B：Google Apps Script（備份）
1. script.google.com → 貼上 `Code.gs`
2. 部署：執行身分=我自己、存取權=所有人
3. 複製 `/exec` 網址 → PWA 設定「雲端備份網址」

### 設定頁（PWA 內）
- **資料查詢網址**（必填）：填 Workers 網址
- **雲端備份網址**（選填）：填 GAS 網址（沿用舊備份）
- **FinMind Token**（選填）：finmindtrade.com 免費註冊，啟用主力縱深卡

| 美元指數/美債殖利率 | Yahoo Finance | 外資匯出壓力總體因子 |

**除權息處理**：等比縮放還原（adjclose因子），比率型指標（RSI/報酬率/乖離%）數學上不受影響；支撐壓力/BOS/CHoCH/智慧停損/劇本/執行計畫統一改用未還原原始市價，貼近真實心理關卡與可下單價位；MAE/MFE 用原始價對齊使用者輸入的進場價。

## 九、設計原則

1. **多維度交叉驗證 > 堆疊指標**：單一訊號再強都不可靠，共振才高勝率
2. **可靠 > 複雜**：拒絕 HMM/Kalman/PCA/VIF 等論文漂亮但對此規模過度工程的方法
3. **透明可解釋**：每個判斷都附證據與白話說明
4. **誠實面對限制**：免費資料做不到的標註清楚；勝率必附 Wilson 信賴區間；機率有校準迴路自我檢驗
5. **數據回饋迴路**：交易日誌 + 盲測對照，驗證系統是否為真 Alpha
6. **反群眾**：知道多少人跟你看到同一個訊號，然後別站在人最多的地方
7. **價格基準一致性**：技術指標用還原價，可下單價位（支撐壓力/停損/劇本）用原始市價，兩者不混用

## 十、AI 協作驗證慣例

本專案由 AI 協作開發。**不論使用哪個模型，每次修改交付前必須通過同一套檢查**：

1. **語法**：全部 JS 檔 `node -c` 通過（含 Code.gs、worker.js）
2. **串接**：HTML 所有 `onclick` 函式已定義；所有 `showHelp(key)` 在 help.js 有對應條目
3. **無幽靈碼**：無重複 HTML id、無跨檔同名函式、無未被呼叫的死碼
4. **完整佈線**：新卡片同時出現在 index.html / layout.js 分頁 / app.js 重置清單 / sw.js 快取清單
5. **數值測試**：新引擎用合成資料做情境測試，驗證方向與範圍正確
6. **價格基準檢查**：新增涉及具體價位的函式時，確認用原始市價還是還原價，並向下相容（無 rawCloses 時 fallback）
7. **Async 競爭防護**：非同步補繪前檢查 `window._activeCode` 是否仍為當前查詢代碼
8. **版本**：config.js APP_VERSION 升號（破快取）
9. **紀律**：不做未要求的修改、樣本太少不調公式參數（防過擬合）、改完說明變動檔案與後端是否需重佈

**匯入交易資料給 AI 優化公式時**：結論須錨定在匯出 MD 的統計表格（順/逆公式 MAE、機率校準度、盲測對照），拒絕沒有數據支持的參數調整。
