# 短線雷達 StockRadar Pro

> 台股／美股量化分析 PWA — 從「市場→產業→個股→機構足跡」多維度決策平台
> 版本 v35｜繁體中文｜手機／Boox e-ink 優化

一個接近量化分析平台雛型的個人交易決策系統。核心理念不是「再多一個技術指標」，而是**多維度交叉驗證 + 看穿主力與散戶行為**——當所有人都用 AI 分析股票，優勢不在看到訊號，而在知道多少人跟你看到同一個訊號。

---

## 一、系統架構

```
前端 (GitHub Pages, 純 JS PWA)
   │
   ├── 資料查詢 ──→ Cloudflare Workers (快, 全球節點)
   │                   └→ Yahoo Finance / TWSE / 期交所
   │
   └── 雲端備份 ──→ Google Apps Script (沿用舊備份)
                       └→ 交易日誌雲端同步

本機儲存：IndexedDB (交易紀錄主要存這，離線可用)
```

**雙後端設計**：查詢走 Workers（快），備份走 GAS（沿用）。兩者功能完全對等（7 個端點），互為備援。

## 二、判斷流水線

系統的分析不是指標堆疊，而是一條決策鏈：

```
① 四態 Regime  ──→ 判斷市場環境（多頭/空頭/盤整/高波動危險），決定該信哪些工具
② MTF 多框架   ──→ 月週日定大方向（大週期定調、小週期找進場）
③ 七維共振      ──→ 趨勢/動能/籌碼/結構/情緒/相對強弱/週期 的共識度
④ 貝氏機率      ──→ 用該股歷史訊號命中率輸出真機率（非燈號）
⑤ 主力行為      ──→ OBV 偷跑偵測，推估吸籌/洗盤/出貨/誘多誘空
⑥ 反明牌雷達    ──→ 量化散戶擁擠度，偵測明牌陷阱
⑦ 智慧停損      ──→ 停損放結構外緩衝區，防被掃後反向走
```

## 四、交易日誌系統（journal.js）

核心設計：**只填 5 格，其餘自動算**。

**只需填**：進場日、出場日、代碼、進場價、出場價
**系統自動**：
- 抓區間 K 線算 MAE（最深虧）/ MFE（最高賺）
- 盈虧%、抱倉天數、自動判定凹單
- 記錄進場日的公式分數（STI/MFD/ECO/PSY/FUSION）
- 方向一致性檢查（順公式/逆公式進場）

**進階功能**：
- 🧪 模擬單（相信系統判斷做的測試單，統計分開看，不污染真實勝率）
- 分批進場 / 加碼（自動算加權平均成本 + 加碼決策分析）
- 分批出場 / 停利（自動算平均出場價 + 停利執行分析）
- 真實勝率 vs 帳面勝率（凹單僥倖判定，解決結果論偏誤）

**Markdown 匯出**（給 AI 優化公式用）：
- 真實 vs 模擬對照
- ★ 進場公式分數 vs 結果對照表（AI 據此調整公式門檻）
- 順公式 vs 逆公式 MAE 統計
- 加碼決策分析、分批出場分析

## 五、反散戶哲學

當一堆人用 AI 分析股票，會產生三個可預測的漏洞，本系統每個都有對應武器：

| AI 散戶的可預測行為 | 本系統的反制 |
|---|---|
| 全部看到同樣教科書訊號（RSI超賣買、金叉買、突破追） | **反明牌雷達**量化擁擠度 |
| 停損全放支撐下方/2×ATR | **智慧停損**放結構外緩衝區 |
| 用槓桿真金白銀照做 | **融資融券**直視散戶部位 |
| 看不到主力 | **OBV 偷跑 + 主力行為推估** |

核心：**擁擠 + 主力反向（OBV降/法人賣）= 明牌陷阱**——散戶照 AI 教科書買，主力照單全收。

## 七、部署

### 前端（GitHub Pages）
1. 所有前端檔案上傳到 repo 根目錄（**不開子資料夾**，相對路徑最穩）
2. Settings → Pages → 選 main 分支根目錄
3. `Code.gs` 與 `worker.js` **不上傳**（那是後端）

### 後端 A：Cloudflare Workers（查詢，推薦）
1. dash.cloudflare.com → Workers & Pages → Create Worker
2. 貼上 `worker.js` → Deploy
3. （選用雲端同步）建立 KV namespace 名為 `SYNC`，綁定到 Worker
4. 複製網址 → PWA 設定「資料查詢網址」

### 後端 B：Google Apps Script（備份）
1. script.google.com → 貼上 `Code.gs`
2. 部署：執行身分=我自己、存取權=所有人
3. 複製 `/exec` 網址 → PWA 設定「雲端備份網址」

### 設定頁（PWA 內）
- **資料查詢網址**（必填）：填 Workers 網址
- **雲端備份網址**（選填）：填 GAS 網址（沿用舊備份）

## 九、設計原則

1. **多維度交叉驗證 > 堆疊指標**：單一訊號再強都不可靠，共振才高勝率
2. **可靠 > 複雜**：拒絕 HMM/Kalman 等論文漂亮但實戰易過擬合的黑箱
3. **透明可解釋**：每個判斷都附證據與白話說明，不是黑箱評分
4. **誠實面對限制**：免費資料做不到的，標註清楚不造假
5. **數據回饋迴路**：交易日誌是專屬護城河，累積後餵回優化公式
6. **反群眾**：知道多少人跟你看到同一個訊號，然後別站在人最多的地方
